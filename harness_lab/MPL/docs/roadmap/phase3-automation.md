# Phase 3: Automation - 자동화 및 최적화 설계

## 목표

Phase 1(Foundation)과 Phase 2(Incremental)에서 수립한 패턴을 자동화하여, 사람의 개입 없이 Phase 0 산출물을 생성하고 토큰 사용을 최적화한다.

## 자동화 영역

### 1. 테스트 파일 자동 파싱 → API 계약 자동 추출

Exp 1에서 수동으로 수행했던 바이트코드/소스 분석을 자동화한다.

#### 설계

```
테스트 파일 입력
      │
      ▼
┌──────────────┐
│ AST 파서     │──→ 함수 호출 추출
│              │──→ 파라미터 순서 추출
│              │──→ 예외 타입 추출
│              │──→ 반환값 패턴 추출
└──────────────┘
      │
      ▼
phase0-api-contracts.md (자동 생성)
```

#### 추출 대상

| 패턴 | AST 노드 | 추출 정보 |
|------|----------|----------|
| 함수 호출 | `ast.Call` | 함수명, 인자 수, 키워드 인자 |
| pytest.raises | `ast.With` + `pytest.raises` | 예외 타입, match 패턴 |
| assert 문 | `ast.Assert` | 기대값, 비교 연산자 |
| fixture 사용 | `ast.FunctionDef` (파라미터) | fixture 이름, 의존성 |
| 타입 체크 | `isinstance` 호출 | 기대 타입 |

#### 구현 계획

```python
class TestAnalyzer:
    """테스트 파일에서 API 계약을 자동 추출한다."""

    def analyze_file(self, test_file: str) -> APIContracts:
        """단일 테스트 파일 분석"""

    def analyze_directory(self, test_dir: str) -> List[APIContracts]:
        """테스트 디렉토리 전체 분석"""

    def generate_contracts_md(self, contracts: List[APIContracts]) -> str:
        """API 계약 문서 자동 생성"""
```

#### 실험 근거

Exp 1에서 수동 바이트코드 분석에 45분이 소요되었다. 자동화하면 이를 수 초로 단축할 수 있다. 특히 다음 패턴의 자동 추출이 가장 큰 가치를 제공한다:
- **파라미터 순서**: `get_ready_tasks(completed, failed, config)` - 수동 발견에 20분 소요
- **예외 타입 매핑**: `pytest.raises(ValueError, match=r'[Cc]ycl')` - 패턴 매칭 자동화
- **기본값 추출**: fixture 정의에서 기본값 자동 수집

### 2. 패턴 자동 분석

Exp 3의 예제 패턴 분석을 자동화한다.

#### 설계

```
테스트 파일 입력
      │
      ▼
┌──────────────┐
│ 패턴 감지기  │──→ 생성 패턴 (객체 인스턴스화)
│              │──→ 검증 패턴 (assert 문)
│              │──→ 에러 패턴 (pytest.raises)
│              │──→ 정렬 패턴 (리스트 비교)
│              │──→ 부수효과 패턴 (상태 변경)
└──────────────┘
      │
      ▼
phase0-examples.md (자동 생성)
```

#### 7개 패턴 카테고리 자동 분류

| 카테고리 | 감지 규칙 | 우선순위 |
|---------|----------|---------|
| 생성 패턴 | 클래스 생성자 호출 | 높음 |
| 검증 패턴 | assert 문 + 비교 연산 | 높음 |
| 에러 패턴 | pytest.raises 블록 | 높음 |
| 정렬 패턴 | 리스트/집합 비교 | 중간 |
| 부수효과 패턴 | assert 후 상태 확인 | 중간 |
| 기본값 패턴 | fixture + 기본 파라미터 | 낮음 |
| 통합 패턴 | 다중 모듈 import | 낮음 |

#### 실험 근거

Exp 3에서 7개 패턴 카테고리를 수동으로 문서화했다. 자동화하면:
- 패턴 누락 방지 (수동 분석에서는 간과하기 쉬운 미묘한 패턴 포착)
- 일관된 문서 형식 보장
- 새 테스트 추가 시 자동 업데이트

### 3. 토큰 사용량 모니터링 및 프로파일링

#### 설계

```
MPL 파이프라인 실행
      │
      ▼
┌──────────────────┐
│ 토큰 프로파일러  │
│                  │
│ Phase 0: ████ 15K│
│ Phase 1: ███ 12K │
│ Phase 2: ███ 12K │
│ Phase 3: ███ 12K │
│ Phase 4: █ 6K    │
│ Phase 5: 0K      │
│ ──────────────── │
│ Total:   57K     │
└──────────────────┘
      │
      ▼
.mpl/profile/run-{timestamp}.json
```

#### 측정 항목

| 항목 | 단위 | 용도 |
|------|------|------|
| Phase별 입력 토큰 | tokens | 컨텍스트 크기 최적화 |
| Phase별 출력 토큰 | tokens | 생성 효율 측정 |
| Phase별 소요 시간 | seconds | 병목 식별 |
| Phase별 API 호출 수 | count | 비용 계산 |
| Phase 5 진입 여부 | boolean | Phase 0 효과 측정 |
| 테스트 통과율 | percentage | 품질 지표 |
| 디버깅 사이클 수 | count | 효율성 지표 |

#### 프로파일 데이터 활용

```python
@dataclass
class RunProfile:
    run_id: str
    timestamp: str
    complexity_level: str
    phases: Dict[str, PhaseProfile]
    total_tokens: int
    total_duration: float
    test_pass_rate: float
    phase5_entered: bool
    debug_cycles: int
```

프로파일 데이터를 축적하여:
1. **복잡도별 최적 토큰 예산** 자동 학습
2. **Phase 0 Step 조합 최적화** (어떤 조합이 가장 효율적인지)
3. **비정상 실행 탐지** (토큰 과다 사용, 과도한 디버깅 사이클)

### 4. Phase 0 산출물 캐싱 및 재사용

#### 설계

동일하거나 유사한 프로젝트에 대해 Phase 0 산출물을 캐싱하여 재사용한다.

```
프로젝트 해시 생성
      │
      ▼
┌──────────────┐    ┌──────────────┐
│ 캐시 조회    │───→│ 히트: 캐시   │──→ Phase 0 스킵
│              │    │ 산출물 로드   │
└──────────────┘    └──────────────┘
      │ 미스
      ▼
┌──────────────┐
│ Phase 0 실행 │──→ 결과 캐시 저장
└──────────────┘
```

#### 캐시 키 설계

```python
cache_key = hash(
    test_files_content,      # 테스트 파일 내용
    project_structure,       # 디렉토리 구조
    dependency_versions,     # 의존성 버전
)
```

#### 캐시 무효화 조건

| 조건 | 동작 |
|------|------|
| 테스트 파일 변경 | 전체 캐시 무효화 |
| 의존성 버전 변경 | 관련 계약만 무효화 |
| 디렉토리 구조 변경 | 구조 관련 캐시만 무효화 |
| 수동 무효화 요청 | 전체 캐시 삭제 |

#### 예상 효과

- **반복 실행 시 Phase 0 토큰 절감**: 8~25K → 0K (캐시 히트 시)
- **CI/CD 통합**: 캐시를 CI 파이프라인 아티팩트로 저장
- **팀 공유**: 캐시를 팀원 간 공유하여 중복 분석 방지

## 통합 자동화 파이프라인

### 전체 흐름

```
프로젝트 입력
    │
    ▼
[복잡도 감지] ──→ 등급 결정
    │
    ▼
[캐시 확인] ──→ 히트? ──→ 캐시 산출물 로드
    │ 미스
    ▼
[자동 Phase 0]
    ├── Step 1: API 계약 자동 추출 (필요 시)
    ├── Step 2: 패턴 자동 분석 (필요 시)
    ├── Step 3: 타입 정책 자동 생성 (필요 시)
    └── Step 4: 에러 명세 자동 생성 (항상)
    │
    ▼
[산출물 캐시 저장]
    │
    ▼
[Phase 1~3: 점진적 구현]
    │
    ▼
[토큰 프로파일 기록]
    │
    ▼
완료
```

## 구현 우선순위

| 우선순위 | 기능 | 예상 효과 | 난이도 |
|---------|------|----------|--------|
| P0 | 에러 명세 자동 생성 | 높음 (30% 테스트 커버리지) | 낮음 |
| P0 | 토큰 프로파일링 | 높음 (최적화 기반) | 낮음 |
| P1 | API 계약 자동 추출 | 높음 (시간 절약) | 중간 |
| P1 | 패턴 자동 분석 | 중간 (품질 개선) | 중간 |
| P2 | 캐시 시스템 | 중간 (반복 실행) | 높음 |
| P2 | 복잡도 자동 감지 | 중간 (적응형) | 중간 |

## 예상 효과 요약

| 지표 | 수동 (현재) | 자동화 (목표) | 개선 |
|------|-----------|-------------|------|
| Phase 0 소요 시간 | 45~60분 | 5~10초 | -99% |
| 패턴 누락률 | 10~20% | <2% | -90% |
| 토큰 가시성 | 없음 | 실시간 프로파일 | 완전 가시화 |
| 반복 실행 비용 | 동일 | ~0 (캐시 히트) | -100% |
| 복잡도 판단 | 주관적 | 객관적 점수 | 일관성 확보 |
